# 전체 소스 점검 및 수정 — 2026-10-11

대상 저장소는 `gmlduqzhd123-lab/lesson-plan`만 사용했습니다. 최초 배포 기록은 `VERIFICATION.md`에 있으며, 이 문서는 후속 전체 점검 결과입니다. 공개 자료는 0개이고, 테스트 자료는 공개 등록하지 않았습니다.

## 발견하여 수정한 오류

1. HWPX 표의 헤더 행 아래에 값이 있는 경우 학년·교과·단원을 놓쳤습니다. 열 대응을 추가하고, 같은 문단의 분리된 텍스트 run은 이어 붙입니다.
2. 표를 역순으로 앞에 삽입해 뒤쪽 section의 학년이 첫 section을 덮었습니다. section·표 순서를 보존합니다.
3. 숫자만 있는 학년과 `학 년`, `교 과` 같은 띄어쓴 필드를 인식하지 못했습니다. 명시 필드의 숫자와 공백을 처리합니다.
4. 문서 필드가 `미상`이어도 파일명 추정을 높은 신뢰도로 표시했습니다. 실제 추출에 성공한 필드만 높은 신뢰도의 근거로 사용합니다.
5. 여러 줄 편집에서 Enter가 만든 빈 줄을 즉시 제거했습니다. 편집 중에는 유지하고, ZIP 직렬화 시에만 빈 항목·앞뒤 공백을 정리합니다.
6. ZIP 생성 중 열린 편집기의 값과 확인 체크를 바꿀 수 있었습니다. 편집 필드·체크를 잠그고 재진입을 차단합니다. ZIP 함수에서도 동의·개수·총 용량을 검증합니다.
7. 같은 파일의 첫 행을 제거해도 남은 중복 행이 계속 차단됐습니다. 목록 제거·공개 목록 갱신·처리 완료 후 해시 중복 상태를 재계산합니다.
8. 관리자 목록 생성 경로의 폴더 링크를 따라 작업 폴더 밖의 파일을 덮어쓸 수 있었습니다. 경로의 모든 폴더와 출력 파일의 링크를 거부하고 JSON을 임시 파일 후 rename으로 교체합니다. 승인 기록 출력 실패 시 추가된 공개 파일을 되돌립니다.
9. 텍스트가 없는 정상 HWPX에 직접 입력을 안내하면서 행은 실패 상태로 막았습니다. 정상 ZIP/XML은 경고와 함께 수동 편집을 허용합니다. 손상 XML·누락 section·외부 엔티티는 계속 거부합니다.
10. HWP 안내에서 OLE 서명만으로 실제 HWP 구조와 암호화 여부까지 확인한 것처럼 읽힐 수 있었습니다. OLE 서명 검사의 제한과 한글에서의 원본 확인 필요성을 명시했습니다.

- 격리된 실제 정적 HTTP 통합 QA: **5개 시나리오 통과**. 브라우저 생성 ZIP의 두 원본을 CLI import/approve/catalog로 등록한 뒤, 요청 대체 없이 검색·상세·원본 다운로드·변조 차단을 검증했습니다.

브라우저 QA의 일부 검색·다운로드 검사는 요청을 fixture 응답으로 대체합니다. 추가 HTTP 통합 QA는 응답 대체 없이 `.tmp/integration-*`의 공개 폴더만 제공합니다. 두 검사 모두 운영 공개 자료를 등록하지 않습니다. 임시 서버는 종료되며 배포 앱의 백엔드가 아닙니다.

재실행: `npm test`, `npm run test:admin`, `npm run build` 후 미리보기를 띄웁니다. `QA_URL`을 미리보기 주소, `QA_OUTPUT`을 `.tmp/audit-local`로 설정하고 `node scripts/browser-qa.mjs`, `node scripts/integration-qa.mjs`를 순서대로 실행합니다. Windows 기본 브라우저는 설치된 Edge이며 다른 환경에서는 `BROWSER_PATH`를 지정합니다.

## 한계 및 실제 배포 구분

실제 교사 HWP/HWPX 표본, 모바일 실기기·iOS Safari, 실제 관리자에게 ZIP 전달은 검증하지 않았습니다. HWPX 그림 OCR과 원본 페이지 렌더링은 없습니다. 개인정보·저작권 검토는 사람이 원본과 미리보기를 확인해야 합니다.

로컬 통과는 수정본 배포 완료를 의미하지 않습니다. 저장소의 해당 커밋에 대한 build/deploy 성공, 공개 HTML·JS·CSS·폰트·catalog와 로컬 dist의 SHA-256 일치, 공개 URL 브라우저 검증 결과는 작업 완료 보고에서 별도로 제공합니다.
